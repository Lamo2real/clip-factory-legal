## Content Rewards (CONTRACTS §38)

The owner signs in to Content Rewards (CR) once on his Mac, and Clip Factory then sends his campaign clips from the
cloud ([CONTRACTS.md §38](CONTRACTS.md#38-content-rewards-campaigns-owner-request-2026-11-21),
[ADR-62](DECISIONS.md#adr-62-content-rewards-the-official-sign-in-through-the-desktop-apps-loopback-door-sending-from-the-cloud-a-reminder-when-it-cant),
[ARCHITECTURE.md flow 19](ARCHITECTURE.md#19-content-rewards-campaigns-contracts-38-adr-62)). Each protection below
ships with its part ([CONTRACTS.md §38.19](CONTRACTS.md#3819-who-builds-what-parallel-builders-each-stays-inside-its-files)),
and the whole feature stayed switched off (`CONTENT_REWARDS=off`, every route 503) until every part had merged; the
switch PR #88 turned it on.

| What | How it is protected |
|---|---|
| The CR token | One secret, `cf-prod/platforms/contentrewards/token` (`accessToken`, `refreshToken`, `expiresAt`, `scope`, `creatorId`, `issuedAt`), created at runtime under the existing prefix, never in Terraform, DynamoDB, logs, responses, URLs, live events, push messages or the durable execution history. The registration (`client_id` and anything CR returns with it) is `cf-prod/platforms/contentrewards/app`. Every reader takes the version named by `CRCONN.tokenVersionId` (never a cached or "current" copy) and never refreshes with a token older than `CRCONN.tokenIssuedAt`. A refresh runs only under the `CRCONN` lease, writes the new secret put-only (a refresh can never re-create a disconnected secret) before the token is used, and throws its result away if the owner disconnected or switched accounts meanwhile. The access token lives 10 minutes; the refresh token is single use, dies after 30 days unused and lasts 90 days at most. |
| Who can reach it | The existing §17.9 grants cover these two secrets, and they are wider than CR needs. Only `cf-prod-api`, `cf-prod-clip-flow` and `cf-prod-stats` ever call CR or read the token for it: `cf-prod-api` creates, writes and deletes both; `cf-prod-clip-flow` and `cf-prod-stats` read both and put only `…/token` (the `token-*` pattern). Two more roles **can** reach them by the same prefix grants although their code never calls CR: `cf-prod-money` (read both, put `…/token`) and `cf-prod-hooks` (read `…/app`; read and write `…/token`, the public callback's role). This is accepted (one owner, the same grants as every platform token) and written down here; narrowing it would mean renaming every platform secret. No other function can read them; `cf-prod-campaigns`, the job flow and the agent in particular have no platform secret access at all. |
| `cf-prod-campaigns` | Reads untrusted brand text and fetches outside files, so its role has **no `secretsmanager:*` action at all** (a Terraform test), no CR call (its fakes have none), and only `campaigns/*` in the media bucket, its table actions and the clip agent's model. The brief it reads is copied onto the `CAMPAIGN#` item first by `cf-prod-api` or `cf-prod-stats`. |
| Never from the browser or the Mac | CR answers 403 to any MCP request with an `Origin` header, and the token is server-side only, so the web app never calls CR and never sees a CR token. The desktop app carries only the one-time code, once. |
| The sign-in door | CR's sign-in returns only to `http://127.0.0.1` (https is refused), so the Mac app opens a door for one sign-in ([§38.15](CONTRACTS.md#3815-desktop-the-one-time-sign-in-door-desktopsrc-taurisrccr_connect)): it binds `127.0.0.1` only (never `0.0.0.0` or `::`) on the first free of the five registered ports `47811–47815`, one door at a time, closed after one good answer, a cancel or 5 minutes. `cr_connect_open` opens only `https://id.contentrewards.com/oauth2/authorize` with every parameter at most once, `code_challenge_method=S256`, a 43-character challenge, exactly one `resource=https://mcp.contentrewards.com/mcp`, a short `state` and `redirect_uri` exactly `http://127.0.0.1:{the open port}/`; anything else is `bad_url`. The door reads one request head (≤ 8 KB, 5 s), only `GET /` with `Host` exactly `127.0.0.1:{port}`, and takes a `code` only with the remembered `state` (compared in constant time); a repeated parameter gets 400, anything else 404 or 400 and the door stays open. Its page is `Cache-Control: no-store`, `Referrer-Policy: no-referrer`, `Content-Security-Policy: default-src 'none'; style-src 'unsafe-inline'`. The code and state stay in memory until the app's page reads them once; they are never logged or written to disk. The four `cr_connect_*` commands are granted at runtime only to the app's own origin in the `main` window (like `mac_fetch`); `capabilities/main.json` stays empty. macOS only: on Windows another program can take a known port, so `listen` answers `unsupported` there. |
| State and PKCE | The same signed single-use state as §17 (`oauth.state`, bound to "contentrewards", 5 minutes, consumed once from `CRSTATE#{nonce}` with a conditional delete); a tampered, expired, reused or cross-platform state ends as `expired`. PKCE S256 with the verifier derived from the nonce and the state key, never stored or sent to the browser. CR's code lives 60 seconds and is single use. `iss`, when present, must equal `https://id.contentrewards.com`. The registration has no client secret (`token_endpoint_auth_method: none`, RFC 7591). Never logged: `code`, `state`, tokens or the query. |
| Scopes | `org:read`, `campaigns:read`, `submissions:read`, `earnings:read` and `my_submissions:write` (send his own post, the same checks as CR's app). No brand scope. Sending is allowed only when the write scope was granted **and** `create_my_submission` is in `tools/list`; else the connection is read only and every post goes to the "send it yourself" reminder. |
| Untrusted brand text | Campaign names, briefs, Google Docs, rejection notes and every link in them are brand text: shown as plain escaped text in the app (never HTML, at most 300 characters a line with **Show more**), put in a marked block for Claude with `<` and `>` written as `\u003c` and `\u003e` (in the rules read and in the agent's `<campaign_rules>`), and never followed as instructions (the system prompt says so). Code then checks Claude's answer field by field ([§38.10](CONTRACTS.md#3810-reading-a-campaign)): every string that can reach a caption, the video or a link must appear word for word in the input; hashtags, tags and the required caption text have fixed patterns and caps (8, 5, 120 characters together; no control, zero-width or bidi characters; at most one `https://` link); the disclosure words come from a fixed list (`#Ad`…, "Paid partnership"), and `render.py` escapes `\`, `{` and `}` and removes line breaks before the on-screen words reach the subtitles; CR's own toggles (drafts first, a sound, the logo) can only add stops; pay, budget, status, access and platforms come only from CR's own fields, never from Claude. |
| Links Clip Factory opens or fetches | Offered as buttons only for https Drive, Dropbox, YouTube, Twitch and Kick links (the kind decided by the host in code, never by Claude); every other link shows as plain text. A channel button is its verbatim https YouTube, Twitch or Kick URL, else a YouTube handle or search URL built in code. The public campaign JSON is read only from `contentrewards.com` (redirects only there, 6 s, 512 KB, no cookies, at most 6 a minute, only when the owner acts). The brand's picture only from `https://crusercontent.com/…` (≤ 1 MB, the type from its first bytes). Google Docs only `https://docs.google.com/document/d/{id}` with a 25–100 character id, read as plain text (6 s, 200 KB), redirects only to `docs.google.com` or `*.googleusercontent.com`. Logo links only on `drive.google.com`, `drive.usercontent.google.com`, `docs.google.com`, `dropbox.com`, `www.dropbox.com`, `dl.dropboxusercontent.com` (redirect hops also `*.dl.dropboxusercontent.com` and `*.googleusercontent.com`, dot-boundary, https only), at most 3 redirects, 10 s, 10 MB, and the first bytes must be PNG, JPEG or WebP (SVG is refused). Google Docs and logo-link fetches send every hop through the `ask/fetch.py` SSRF guard (public addresses only), with no cookies; a redirect to a sign-in page means "not shared" for a logo link and "I couldn't tell" for a Google Doc. The CSP is unchanged: brand pictures are served from the media bucket. |
| Logo uploads | Presigned PUT (15 min) for PNG, JPEG or WebP up to 10 MB to the caller's own `campaigns/{userId}/{uuid}/` key; `…/logo/done` checks the size and the first bytes (PNG, JPEG or WebP), else answers 400 with the §38.4 sentence; after a good upload the older logo file is deleted. Jobs get their own copy under `jobs/{jobId}/source/`; the agent never reads `campaigns/`. |
| Posts stay up | No publisher or adapter has a delete, unpublish or privacy-change call (a test reads the classes); removing a campaign or disconnecting CR deletes nothing on CR or any platform; job delete keeps campaign posts and `CRSUB#` items. Campaign clips are public, never made for kids, and marked as paid where the platform's API allows. |
| Logs and feedback | CR's `request_id` is logged with each CR error; `code`, `state`, tokens and the query never are. Unknown or "bug on our side" errors go to CR's `send_feedback` at most once per code per day, with no personal data, URLs or tokens. |
| Disconnect | Under the same lease: revoke the refresh token (best effort), delete the token secret, `CRCONN` → `not_connected`. Campaigns, submissions and money items stay. To remove the app on CR too: CR Settings › **Connected apps** › **Disconnect**. |
