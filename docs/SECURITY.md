# Security

## The owner's stance

The owner asked for convenience over strictness: "I don't care about security at all. Just make sure that I don't
have to log in every single day or every single week." So the app keeps sign-ins rare, has no multi-factor prompt,
and merges and deploys without a human approval step.

Convenience does not mean open. The app holds the owner's videos, unpublished clips, skills, YouTube cookies and
the keys to the owner's social accounts. Everything below stays on because it costs the owner nothing
in daily use.

## Sign-in and tokens

| Setting | Value | What it means for the owner |
|---|---|---|
| Users | One, created by Terraform from `CF_OWNER_EMAIL`; sign-up is off | Nobody else can create an account. |
| Sign-in | The app's own screen, Secure Remote Password (SRP) through Amplify | The password is never sent in clear text, not even over HTTPS. |
| Access and ID tokens | 15 minutes | Refreshed silently in the background; the owner never notices. |
| Refresh token | 30 days, **rotated on every refresh**, 10-second grace period | Every refresh issues a new 30-day refresh token. Using the app at least once a month means never signing in again. After 30 days away, one sign-in. |
| Token revocation | On | Signing out revokes the refresh token. |
| User existence errors | Hidden | A wrong email and a wrong password give the same message. |
| MFA | Off | Owner's choice. Can be turned on later in Cognito without code changes. |

Tokens are stored by Amplify in the browser's local storage on each device. Signing out on one device does not sign
out others until their refresh token is used and found revoked.

## What is protected and how

| Asset | Protection |
|---|---|
| HTTP API | Every route except `/v1/health` needs a valid access token (API Gateway JWT authorizer: issuer, audience, expiry). The user id comes from the token's `sub`, never from the request body, so one user can never reach another's data. |
| Live updates (WebSocket API) | `$connect` needs a valid Cognito **access** token, checked by `cf-prod-ws-authorizer`: RS256 signature against the pool's published keys, issuer, `token_use = access`, the app client id and expiry (no leeway). Each connection is tied to the token's `sub`, and the broadcaster sends only that owner's changes, in the public shape (no internal fields). Connections expire after 2 hours. |
| The token in the WebSocket URL | Browsers cannot send headers on a WebSocket, so the token travels in the `$connect` query string over TLS. It is never logged: the stage access log has a fixed field list (request id, connection id, event, route, status, time, errors) with no query and no headers, data tracing is off, execution logging is at `ERROR`, and the Lambdas never log the token or the raw query. The token itself lives 15 minutes. |
| Platform webhooks (REST API) | Public by design (platforms cannot hold the owner's token), so it is kept apart from the app API: only `/hooks/{platform}` and `/oauth/{platform}/callback`, unknown platforms get 404, bodies over 256 KB get 413, each method is throttled to 10 requests a second (burst 20) with a monthly usage-plan ceiling, and the handler only stores the event (14-day TTL) or answers a challenge. Webhook events can write nothing but `HOOK#` items; the OAuth callback is described in [Platform keys and tokens](#platform-keys-and-tokens). Access logs leave out the query string (OAuth `code` and `state`). Webhook signature checks are not built yet: events are stored as `unverified` and nothing acts on them. |
| Platform stats tokens | Read from Secrets Manager (`cf-prod/platforms/*`) by `cf-prod-stats` and the clip flow's `metrics` step; never written to DynamoDB, logs, responses or WebSocket events. The refresh route never accepts a platform id or URL from the browser: it reads the clip's own posts. Internal stats fields (`statsId`, `refreshStartedAt`, `statsDueAt`, budgets) never leave the API. |
| Meta verify token | An SSM SecureString (`aws/ssm` key), generated by Terraform as a write-only value so it is never in the Terraform state; compared in constant time. |
| Durable flows | Each flow has its own role: checkpoint access only to its own executions (`function:<name>:*`), and only the table, bucket paths, models and vector index it uses. Only the agent's role may send job-flow callbacks, and only to `cf-prod-job-flow`. Execution history (inputs, step results) is kept 14 days and holds ids and statuses, no tokens. |
| Learning memory (S3 Vectors) | Private vector bucket, encrypted at rest (SSE-S3). Every query filters on the caller's `userId`; `/similar` also checks the clip belongs to the caller. Vectors hold clip text and numbers, never media or tokens. A clip thrown away loses its vector. |
| Videos, clips, skills | Private S3 bucket, encryption at rest (SSE-S3), Block Public Access on. Browsers get presigned URLs that expire after 1 hour. |
| Skill text | Written by the owner, so treated as untrusted text in two places. **In the app** it is shown with the app's own markdown renderer, never as HTML: raw HTML stays text, only `http`, `https` and `mailto` links work, images are never loaded, and a test fails if anything uses `dangerouslySetInnerHTML`. **In prompts** it sits inside `<owner_skills>` and is followed only as far as the task's own rules and answer format allow; the agent's hard rules (never publish, only clip what is in the source) still win. Skill files are only ever read by key from the owner's own DynamoDB items: `cf-prod-clip-flow` and `cf-prod-learn` get `s3:GetObject` on `skills/*` and no list. Uploads and edits accept only the caller's own `skills/{userId}/{skillId}/…` keys. |
| YouTube cookies | Stored at `private/<userId>/youtube-cookies.txt`. The API can replace or delete them but never returns them; only the agent reads them, for yt-dlp. |
| Web app | Private S3 bucket readable only by CloudFront (Origin Access Control). HTTPS only. |
| Database | DynamoDB encrypted at rest, point-in-time recovery for 35 days. |
| AWS access from CI | GitHub OIDC; the deploy role trusts only `main` of `Lamo2real/clip-factory-legal`. No stored AWS keys. |
| Runtime permissions | One IAM role per Lambda and one for the agent runtime. `cf-prod-stats` can only read and write the table and read and refresh platform tokens (no Bedrock, no vectors); only `cf-prod-api`, `cf-prod-hooks`, `cf-prod-clip-flow`, `cf-prod-stats` and `cf-prod-money` reach `cf-prod/platforms/*` in Secrets Manager; `cf-prod-clip-flow`, `cf-prod-stats` and `cf-prod-money` can write only the token secrets (`cf-prod/platforms/*/token-*`), and `cf-prod-hooks` reads the app keys and writes only tokens and pending choices; `cf-prod-money` (§25) has exactly `cf-prod-stats`' secret access and no DeleteItem; `cf-prod-learn` adds Bedrock and the vector index; `cf-prod-api` may call only `bedrock:InvokeModel` on the help model's EU inference profile and its six EU foundation models (statement `HelpModel`); only the EventBridge rule and `cf-prod-api` may invoke `cf-prod-stats`. Each can reach only the table actions, bucket paths, models, vector index and API it needs. The WebSocket authorizer has no AWS permissions beyond its logs. The agent may call `bedrock:InvokeModel` on the watch model's EU profile and its six EU foundation models (statement `InvokeWatchModel`) besides Fable and Titan, and has no Rekognition, Comprehend, MediaConvert, Step Functions or Batch action (tested in `infra/modules/agent/tests`). The agent cannot publish, change IAM or touch infrastructure. `cf-prod-campaigns` (Content Rewards rules and logos) has no Secrets Manager action at all and only `campaigns/*` in the media bucket ([below](#content-rewards-contracts-38)). |
| Model data | Claude Fable 5.1 runs through the global cross-Region profile, so prompts (transcripts, hooks, captions, and since [ADR-40](DECISIONS.md#adr-40-watch-the-whole-video-before-picking) **frames of the whole source video**: the same class of data as the one facecam frame per clip before, but far more of it) may be processed outside the EU, and with the required `aws_review` data-retention mode AWS may keep them up to 30 days for human review (not shared with Anthropic). Titan embeddings run in `eu-north-1`. The second watcher, Amazon Nova 2 Lite, gets small video parts of the source through the **EU** profile only (eu-central-1, eu-north-1, eu-south-1, eu-south-2, eu-west-1, eu-west-3; the agent's IAM statement `InvokeWatchModel` names exactly that profile and those six foundation models, no wildcard). No frame or video part is stored outside the media bucket in Stockholm (`jobs/{jobId}/source/picture/`, expired after 14 days), and no new bucket or Region holds data at rest. Help questions go to Claude Haiku 5.5 through the **EU** profile only (EU Regions), and only after search found a match; they are not stored by Clip Factory. Media and data at rest stay in Stockholm. |
| Ask Clip Factory (help assistant) | Two routes behind the same JWT as every `/v1` route ([CONTRACTS.md §19](CONTRACTS.md#19-ask-clip-factory-grounded-in-app-help-assistant-owner-request-2026-11-16)). It reads **no** clips, posts, weeks or settings for its answers: live numbers are fetched by the browser from the existing routes with the owner's own token. Questions, history, answers and skills are never stored and never logged (one outcome line with a request id per request; the generic access line has no body). The question, history and knowledge go to the model as JSON data fields, and the system prompt says they are data, not instructions; the owner's skills block comes first, as in every model call ([§18.6](CONTRACTS.md#18-skills-full-create-read-update-delete-every-ai-call-uses-every-skill-owner-request-2026-11-16)), and the grounding rules after it say the skills never override facts from the knowledge. Model output is checked: action ids must come from this request's matches, and every bold button name, path and number must appear in the matches; an answer with a link or a domain the matches do not hold, or one that repeats a price the owner typed (a number from the question with a money word or currency sign within 24 characters), is thrown away too, and the plain answer is used (outcome `kb_ungrounded`). The model client makes one attempt only (no retry). History from the browser is never trusted for buttons. Questions about passwords, keys, tokens, the cookie file's contents, other people's accounts or clips, or the servers get a fixed refusal with no model call. |
| Help knowledge (corpus) | Generated from the app's own source at build time; a filter drops ARNs, account numbers, AWS key ids, emails, `s3://` and signed URLs, and words such as password, secret, token, lambda, dynamodb, bedrock, cognito; a test fails if any survive. The API fetches the deployed copy only from `APP_URL`: it reads the `cf-help-corpus` meta tag in `index.html` and accepts only `/assets/help-corpus.<12 hex>.json` on the same origin (no other host is ever fetched; 3 s timeouts, 512 KB and 2 MB size limits), validates it, and otherwise keeps the last good copy or the copy bundled in the Lambda zip. |
| Pictures in Ask | [CONTRACTS.md §26](CONTRACTS.md#26-pictures-in-ask-owner-request-2026-11-19), [ADR-48](DECISIONS.md#adr-48-ask-pictures-go-inline-are-read-once-into-words-and-are-never-stored). Up to 4 pictures per question exist only in the browser's memory (object URLs, revoked on Start over, on sign-out and past 12 kept) and in that one request; nothing is written to DynamoDB, S3 or logs (the log line has only a count and a size). The browser re-encodes each picture through a canvas (the photo's EXIF and GPS are left behind) and drops every APP1..APP15 and COM segment; the API checks each one (strict base64, a JPEG with a baseline or progressive frame, at most 600 KB and 1600 px) and drops APP1..APP15 and COM again before Bedrock. The model reads them through the same EU profile as help questions; text in a picture is data, never instructions, and what it reads (`words`, `seen`) passes the sensitive filter, loses links, email addresses and long digit runs, and can only change which help doc search finds: answers stay grounded as above, and refusals run on the typed question only. Bedrock model-invocation logging stays off (a test fails if `infra/` defines it). 40 picture questions per owner per day and a `pictures` switch attribute bound the cost. |
| Help cost and abuse | Per owner 6 questions a minute and 60 an hour, 2,000 model answers per 30 days, each reserved with one conditional DynamoDB write; over the limit answers `429` with `Retry-After`, which the app never retries by itself. A deploy flag and a kill-switch item turn it off without a deploy, and the switch also stops the app's local fallback. |
| Owner email | A GitHub secret, so it is masked in the logs of this public repository. |
| Social app keys and account tokens | AWS Secrets Manager only, never DynamoDB, logs, responses, URLs or the browser after the owner pastes them ([details](#platform-keys-and-tokens)). |
| Content Rewards | One sign-in through the Mac app's loopback door; the token only in Secrets Manager and used only by `cf-prod-api`, `cf-prod-clip-flow` and `cf-prod-stats`; brand text is untrusted and checked by code; the reader of brand text (`cf-prod-campaigns`) has no secret access ([details](#content-rewards-contracts-38)). |
| Publishing | Only after the owner presses Keep on that clip (and, for TikTok, fills in the Post to TikTok sheet). The agent has no permission to publish or to read platform secrets. |
| Desktop app | Opens only the app's own address; any other link opens in the normal browser. It holds no keys or secrets, and sign-in works exactly as in a browser. Built by GitHub Actions from this repository and served from the private web bucket over HTTPS. |

## Platform keys and tokens

The owner pastes each platform's app keys into the setup ([SETUP_POSTING.md](SETUP_POSTING.md)) and presses Connect
([CONTRACTS.md §17.4–17.6](CONTRACTS.md#174-api-all-jwt-5-errors-routessetuppy-package-clipfactory_apioauth)).

| What | How it is protected |
|---|---|
| App keys (`clientId`, `clientSecret`, `configId`) | Sent once over HTTPS to `PUT /v1/setup/{platform}/keys` (JWT), written to Secrets Manager `cf-prod/platforms/{platform}/app`, never returned. Responses, DynamoDB and live events carry only masked hints (first 6 and last 4 characters of the public id, "••••" and the last 4 of a secret). The paste box is cleared after saving. |
| Account tokens | Written by `cf-prod-hooks` after the code exchange to `cf-prod/platforms/{platform}/token`; refreshed by `cf-prod-clip-flow` and `cf-prod-stats`. Instagram signs in with a Facebook **user** access token (exchanged for the long-lived one), but only the chosen Page's access token is kept here, with the Instagram account id and Page id; the user token is never stored. Posting and numbers use the Page token. Meta's several-account choices wait in `…/pending` for at most 30 minutes. Never in DynamoDB, logs, responses, URLs, WebSocket events or the durable execution history (steps return ids, not tokens). |
| Secret lifecycle | Created at runtime with `CreateSecret` (tags `app=cf-prod`, `platform`), updated with `PutSecretValue`, deleted with `ForceDeleteWithoutRecovery` on Disconnect or key delete. Logs name the secret, never its value. |
| Who may read them | `cf-prod-api` (create, put, get, describe, delete on `cf-prod/platforms/*`), `cf-prod-hooks` (public, so the narrowest: get and describe only on the `app` secrets `cf-prod/platforms/*/app*`; create, put, get, describe on the token secrets `cf-prod/platforms/*/token*`; the same plus delete on the `pending` secrets `cf-prod/platforms/*/pending*`. No `-` before the `*`, because for a secret that does not exist yet Secrets Manager checks the bare name, and the callback needs "not found", not "access denied", to create it), `cf-prod-clip-flow` and `cf-prod-stats` (get on `cf-prod/platforms/*`, but put only on the token secrets `cf-prod/platforms/*/token-*`, the ARN pattern Terraform passes in as `platform_token_secrets_arn`). Only `cf-prod-api` can write or delete the `app` secrets; only `cf-prod-api` and `cf-prod-hooks` can write the `pending` secrets. `cf-prod-hooks` reaches only the `HOOK#`, `OAUTH#` and `USER#` partitions of the table (`dynamodb:LeadingKeys`); after a connect it may set the owner's waiting posts to queued and start `cf-prod-clip-flow` (any qualifier of that one function, no other), so a post never goes anywhere the owner did not upload it to (CONTRACTS §17.6). The job flow, the agent, the WebSocket Lambdas and `cf-prod-learn` have no Secrets Manager access. |
| Connect state | `state = v1.{nonce}.{exp}.{HMAC-SHA256}` with the key in `cf-prod/oauth/state-key` (generated by Terraform as a write-only value, never in its state), valid 10 minutes, bound to the platform, and consumed once with a conditional delete of `OAUTH#{nonce}`. A tampered, expired, reused or cross-platform state ends as "That took too long". |
| PKCE | S256 for YouTube and X. The verifier is derived from the nonce with the state key, so it is never stored or sent to the browser. TikTok and Meta use the client secret on the server instead. |
| Redirects | Every platform has one exact redirect URI, `{hooks_url}/oauth/{platform}/callback`, compared exactly by the platform. The callback always answers `302` to `{app_url}/settings/posting/setup/{platform}?result={code}` with a code from a fixed list: nothing from the request is reflected, so it cannot be an open redirect. `Cache-Control: no-store`, `Referrer-Policy: no-referrer`. The code, state and query are never logged. |
| Scopes | Only what posting and numbers need (CONTRACTS §17.7). A missing permission is detected and reported; Meta calls send `appsecret_proof`. |
| Disconnect and data | Disconnect revokes the token where the platform allows it, deletes the token secret and marks the account `not_connected`. For YouTube it also removes stored YouTube numbers (`forget`), as YouTube's Developer Policies require after revocation. Facebook keeps only the Page token, which cannot revoke the app, so the owner removes the app in Facebook's Business integrations settings ([After setup](SETUP_POSTING.md#after-setup)). |
| TikTok verification file | `POST /v1/setup/tiktok/verification-file` accepts only `tiktok*.txt` names and at most 4 KB of printable text, and writes only `tiktok*` keys in the web bucket. |
| Public pages | `about.html`, `legal/privacy.html` and `legal/terms.html` are static and hold no data. |

## Content Rewards (CONTRACTS §38)

The owner signs in to Content Rewards (CR) once on his Mac, and Clip Factory then sends his campaign clips from the
cloud ([CONTRACTS.md §38](CONTRACTS.md#38-content-rewards-campaigns-owner-request-2026-11-21),
[ADR-62](DECISIONS.md#adr-62-content-rewards-the-official-sign-in-through-the-desktop-apps-loopback-door-sending-from-the-cloud-a-reminder-when-it-cant),
[ARCHITECTURE.md flow 19](ARCHITECTURE.md#19-content-rewards-campaigns-contracts-38-adr-62)). Each protection below
ships with its part ([CONTRACTS.md §38.19](CONTRACTS.md#3819-who-builds-what-parallel-builders-each-stays-inside-its-files)),
and the whole feature stayed switched off (`CONTENT_REWARDS=off`, every route 503) until every part had merged; the
switch PR #88 turned it on.

| What | How it is protected |
|---|---|
| The CR token | One secret, `cf-prod/platforms/contentrewards/token` (`accessToken`, `refreshToken`, `expiresAt`, `scope`, `creatorId`, `issuedAt`), created at runtime under the existing prefix, never in Terraform, DynamoDB, logs, responses, URLs, live events, push messages or the durable execution history. The registration (`client_id` and anything CR returns with it) is `cf-prod/platforms/contentrewards/app`. Every reader takes the version named by `CRCONN.tokenVersionId` (never a cached or "current" copy) and never refreshes with a token older than `CRCONN.tokenIssuedAt`. A refresh runs only under the `CRCONN` lease, writes the new secret put-only (a refresh can never re-create a disconnected secret) before the token is used, and throws its result away if the owner disconnected or switched accounts meanwhile. The access token lives 10 minutes; the refresh token is single use, dies after 30 days unused and lasts 90 days at most. |
| Who can reach it | The existing §17.9 grants cover these two secrets, and they are wider than CR needs. Only `cf-prod-api`, `cf-prod-clip-flow` and `cf-prod-stats` ever call CR or read the token for it: `cf-prod-api` creates, writes and deletes both; `cf-prod-clip-flow` and `cf-prod-stats` read both and put only `…/token` (the `token-*` pattern). Two more roles **can** reach them by the same prefix grants although their code never calls CR: `cf-prod-money` (read both, put `…/token`) and `cf-prod-hooks` (read `…/app`; read and write `…/token`, the public callback's role). This is accepted (one owner, the same grants as every platform token) and written down here; narrowing it would mean renaming every platform secret. No other function can read them; `cf-prod-campaigns`, the job flow and the agent in particular have no platform secret access at all. |
| `cf-prod-campaigns` | Reads untrusted brand text and fetches outside files, so its role has **no `secretsmanager:*` action at all** (a Terraform test), no CR call (its fakes have none), and only `campaigns/*` in the media bucket, its table actions and the clip agent's model. The brief it reads is copied onto the `CAMPAIGN#` item first by `cf-prod-api` or `cf-prod-stats`. |
| Never from the browser or the Mac | CR answers 403 to any MCP request with an `Origin` header, and the token is server-side only, so the web app never calls CR and never sees a CR token. The desktop app carries only the one-time code, once. |
| The sign-in door | CR's sign-in returns only to `http://127.0.0.1` (https is refused), so the Mac app opens a door for one sign-in ([§38.15](CONTRACTS.md#3815-desktop-the-one-time-sign-in-door-desktopsrc-taurisrccr_connect)): it binds `127.0.0.1` only (never `0.0.0.0` or `::`) on the first free of the five registered ports `47811–47815`, one door at a time, closed after one good answer, a cancel or 5 minutes. `cr_connect_open` opens only `https://id.contentrewards.com/oauth2/authorize` with every parameter at most once, `code_challenge_method=S256`, a 43-character challenge, exactly one `resource=https://mcp.contentrewards.com/mcp`, a short `state` and `redirect_uri` exactly `http://127.0.0.1:{the open port}/`; anything else is `bad_url`. The door reads one request head (≤ 8 KB, 5 s), only `GET /` with `Host` exactly `127.0.0.1:{port}`, and takes a `code` only with the remembered `state` (compared in constant time); a repeated parameter gets 400, anything else 404 or 400 and the door stays open. Its page is `Cache-Control: no-store`, `Referrer-Policy: no-referrer`, `Content-Security-Policy: default-src 'none'; style-src 'unsafe-inline'`. The code and state stay in memory until the app's page reads them once; they are never logged or written to disk. The four `cr_connect_*` commands are granted at runtime only to the app's own origin in the `main` window (like `mac_fetch`); `capabilities/main.json` stays empty. macOS only: on Windows another program can take a known port, so `listen` answers `unsupported` there. |
| State and PKCE | The same signed single-use state as §17 (`oauth.state`, bound to "contentrewards", 5 minutes, consumed once from `CRSTATE#{nonce}` with a conditional delete); a tampered, expired, reused or cross-platform state ends as `expired`. PKCE S256 with the verifier derived from the nonce and the state key, never stored or sent to the browser. CR's code lives 60 seconds and is single use. `iss`, when present, must equal `https://id.contentrewards.com`. The registration has no client secret (`token_endpoint_auth_method: none`, RFC 7591). Never logged: `code`, `state`, tokens or the query. |
| Scopes | `org:read`, `campaigns:read`, `submissions:read`, `earnings:read` and `my_submissions:write` (send his own post, the same checks as CR's app). No brand scope. Sending is allowed only when the write scope was granted **and** `create_my_submission` is in `tools/list`; else the connection is read only and every post goes to the "send it yourself" reminder. |
| Untrusted brand text | Campaign names, briefs, Google Docs, rejection notes and every link in them are brand text: shown as plain escaped text in the app (never HTML, at most 300 characters a line with **Show more**), put in a marked block for Claude with `<` and `>` written as `\u003c` and `\u003e` (in the rules read and in the agent's `<campaign_rules>`), and never followed as instructions (the system prompt says so). Code then checks Claude's answer field by field ([§38.10](CONTRACTS.md#3810-reading-a-campaign)): every string that can reach a caption, the video or a link must appear word for word in the input; hashtags, tags and the required caption text have fixed patterns and caps (8, 5, 120 characters together; no control, zero-width or bidi characters; at most one `https://` link); the disclosure words come from a fixed list (`#Ad`…, "Paid partnership"), and `render.py` escapes `\`, `{` and `}` and removes line breaks before the on-screen words reach the subtitles; CR's own toggles (drafts first, a sound, the logo) can only add stops; pay, budget, status, access and platforms come only from CR's own fields, never from Claude. |
| Links Clip Factory opens or fetches | Offered as buttons only for https Drive, Dropbox, YouTube, Twitch and Kick links (the kind decided by the host in code, never by Claude); every other link shows as plain text. A channel button is its verbatim https YouTube, Twitch or Kick URL, else a YouTube handle or search URL built in code. The public campaign JSON is read only from `contentrewards.com` (redirects only there, 6 s, 512 KB, no cookies, at most 6 a minute, only when the owner acts). The brand's picture only from `https://crusercontent.com/…` (≤ 1 MB, the type from its first bytes). Google Docs only `https://docs.google.com/document/d/{id}` with a 25–100 character id, read as plain text (6 s, 200 KB), redirects only to `docs.google.com` or `*.googleusercontent.com`. Logo links only on `drive.google.com`, `drive.usercontent.google.com`, `docs.google.com`, `dropbox.com`, `www.dropbox.com`, `dl.dropboxusercontent.com` (redirect hops also `*.dl.dropboxusercontent.com` and `*.googleusercontent.com`, dot-boundary, https only), at most 3 redirects, 10 s, 10 MB, and the first bytes must be PNG, JPEG or WebP (SVG is refused). Google Docs and logo-link fetches send every hop through the `ask/fetch.py` SSRF guard (public addresses only), with no cookies; a redirect to a sign-in page means "not shared" for a logo link and "I couldn't tell" for a Google Doc. The CSP is unchanged: brand pictures are served from the media bucket. |
| Logo uploads | Presigned PUT (15 min) for PNG, JPEG or WebP up to 10 MB to the caller's own `campaigns/{userId}/{uuid}/` key; `…/logo/done` checks the size and the first bytes (PNG, JPEG or WebP), else answers 400 with the §38.4 sentence; after a good upload the older logo file is deleted. Jobs get their own copy under `jobs/{jobId}/source/`; the agent never reads `campaigns/`. |
| Posts stay up | No publisher or adapter has a delete, unpublish or privacy-change call (a test reads the classes); removing a campaign or disconnecting CR deletes nothing on CR or any platform; job delete keeps campaign posts and `CRSUB#` items. Campaign clips are public, never made for kids, and marked as paid where the platform's API allows. |
| Logs and feedback | CR's `request_id` is logged with each CR error; `code`, `state`, tokens and the query never are. Unknown or "bug on our side" errors go to CR's `send_feedback` at most once per code per day, with no personal data, URLs or tokens. |
| Disconnect | Under the same lease: revoke the refresh token (best effort), delete the token secret, `CRCONN` → `not_connected`. Campaigns, submissions and money items stay. To remove the app on CR too: CR Settings › **Connected apps** › **Disconnect**. |

## CORS

The API allows only the app's CloudFront address and `http://localhost:5173` (local development), and exposes one
response header, `retry-after`, so the help panel can show its countdown. Media bucket CORS
allows `PUT` from the same origins for uploads.

## What is deliberately relaxed

- No MFA, long-lived sessions (30 days, rotating).
- Pull requests merge automatically when CI is green, and `main` deploys without approval. CI is the gate.
- The deploy role may use broad permissions (`PowerUserAccess`), because only `main` of this repository can assume
  it. It still cannot make itself an administrator: IAM is limited to `cf-prod-*` roles that carry the
  `cf-prod-role-boundary` permissions boundary ([DEPLOYMENT.md](DEPLOYMENT.md) section 2), and the desktop build job,
  which runs npm and cargo, cannot ask for its OIDC token.
- No AWS WAF in front of CloudFront or the APIs (cost, one user; the JWT and WebSocket authorizers reject everything
  else, and the public REST API is throttled). A WAF web ACL can be attached to the REST API stage later.
- Webhook signatures are not verified yet; stored events trigger nothing.
- The platform-secret grants are shared by prefix, so the Content Rewards token can be read by `cf-prod-money` and
  `cf-prod-hooks` too, although neither ever calls Content Rewards ([Content Rewards](#content-rewards-contracts-38)).
- The owner's Google app is **published but not verified** ([ADR-33](DECISIONS.md#adr-33-posting-setup-bring-your-own-keys-with-a-guided-list-per-platform)):
  Google shows "Google hasn't verified this app" on Connect, which is expected for an app only its owner uses.
  Instagram's Meta app stays in Development mode. Neither widens who can use the app: only the owner's accounts
  can connect, and only the owner can sign in to Clip Factory.
- The desktop `.dmg` and `.exe` are not code-signed yet ([ADR-19](DECISIONS.md#adr-19-unsigned-desktop-builds-for-now)).
  Download them only from the app's own Get the app card, never from a copy someone sends you.

## Ask as a full assistant (CONTRACTS §28)

* **Prompt injection.** Web pages, search results, files and pictures are data: the rules say never follow
  instructions inside them, and the tools make it safe even if the model did. Ask has no tool that writes, posts,
  deletes, connects or sends. `web_fetch` opens only URLs from this answer's search results, an earlier answer's
  sources (sent back by the panel) or URLs the owner typed himself, so a page cannot chain fetches or carry his data
  out in a URL. APP STATE, which the model reads with system weight, holds only enums, numbers, ids, booleans and
  Clip Factory's own step titles: clip hooks, raw error text and account names (words others or a model wrote) reach
  the model only as tool results. Only those URLs become live links, and only
  after the answer is done; any other URL shows as plain text.
* **SSRF.** `web_fetch` is https only; every address must be public (private, loopback, link-local, CGNAT, metadata,
  multicast and reserved addresses are refused, and so are IPv6 forms that carry an IPv4 address: NAT64, 6to4 and
  Teredo) and is checked again on each of at most 3 redirects; the connection goes to the checked address; one
  deadline for the whole fetch (DNS 2 s, every request at most 6 s, at most 10 s in all and never past the answer's
  hard budget), so a page that trickles bytes cannot hold the worker past its Lambda timeout; 2 MB, four content
  types, no cookies or auth headers. The worker checks Stop and the hard budget before every round of tools.
* **Secrets.** Questions asking to be shown his own stored password, key, token or cookie contents get a fixed answer
  with no model call (their files are deleted); questions about keys in general are answered (Ask can't read any
  secret). The knowledge pack, APP STATE, text files and office files pass the wide secrets filter (keys, tokens,
  account ids, ARNs, emails, URLs with a query). Every streamed answer passes a narrow filter (private key blocks,
  `AKIA`/`ASIA` keys, `sk-`/`ghp_`/`xox` style keys and his stored search key), with a 64-character hold-back that
  never cuts inside an unbroken token and holds a private key block back until its END, so a key split across many
  deltas never leaves. APP STATE never
  carries tokens, keys, secret names, ARNs, emails or OAuth state. The web search key lives only in Secrets Manager.
* **Files.** Uploaded with presigned PUTs (type and length signed) to `ask/{sub}/`, read once and deleted as soon as
  they are in memory (again when the answer ends); the API deletes them on every start that does not return 202 and
  the panel on every ending where the question did not start; the 1-day lifecycle rule is the safety net (S3 expires
  once a day, so a forgotten file lives at most about 2 days). Office files are read with zip-bomb limits and no DTDs.
* **Logs.** One line per answer with ids, counts, timings, tokens and the outcome; never the question, answer, file
  names or contents, URLs, search queries or the key. Bedrock model invocation logging stays off (a drift test).
* **IAM.** `cf-prod-fn-ask` may call only the two Ask models (`bedrock-mantle:Model` condition), read and delete
  `ask/*`, read skill files, read the table (`GetItem` and `Query` only: no writes of any kind), post to WebSocket
  connections and read the search key. The search key permissions name exactly `cf-prod/ask/search-key-??????` (the
  name plus the 6-character suffix Secrets Manager adds), never a trailing `*`. The key is cached 60 s in a warm
  worker, so **Take key away** is felt within a minute.

## If something goes wrong

- **Lost device**: in the Cognito console, open `cf-prod-users` → Users → your user and sign the user out globally
  (`AdminUserGlobalSignOut`), which revokes every refresh token. Then reset the password from the same page.
- **Leaked cookies file**: delete it in Settings (or `DELETE /v1/settings/cookies`) and sign out of YouTube in the
  browser it came from, which invalidates those cookies.
- **Suspicious deploy**: check the Actions run that produced it; revert on `main`.
- **Leaked webhook verify token**: change the parameter's value version in Terraform (`value_wo_version`) and deploy;
  then paste the new value into the platform console.
- **A leaked platform key** (Client secret or App secret): make a new secret on the platform (Google **Add secret**
  then **Disable** the old one; TikTok, Meta and X **Reset** or **Regenerate**), paste it in Settings › Posting › Set up
  posting › {Platform} › **Save keys**, then **Connect again**. To cut a platform off at once, press **Disconnect**
  (it revokes the token where the platform allows it and deletes the token secret) or remove the app's access on the
  platform (for Google: <https://myaccount.google.com/permissions>).
- **Content Rewards: an unknown sign-in or a lost Mac**: press **Disconnect** in Settings › Posting › Set up posting ›
  Content Rewards (it revokes the refresh token and deletes the token secret), then on Content Rewards open Settings ›
  **Connected apps** and press **Disconnect** next to Clip Factory. Nothing on any platform is deleted. Connect again
  on the Mac when you want it back.
- **The help assistant says something wrong or unwanted**: set the kill switch (`HELP` / `SWITCH`, `enabled: false`, or
  `model: false` to keep answers from search only) with the command in
  [DEPLOYMENT.md](DEPLOYMENT.md#ask-clip-factory-kill-switch); it takes effect within 60 seconds, no deploy needed.
- **A live connection you do not recognise**: sign out globally (above). Existing connections close within 2 hours at
  the latest, and no new one opens without a valid token.
